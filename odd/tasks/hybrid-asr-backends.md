# Hybrid ASR backends (DirectML/ORT for AMD/Intel/CPU, CUDA-optimized path for NVIDIA)

Locator: `odd/tasks/hybrid-asr-backends.md` · Engram mirror: `odd/hybrid-asr-backends/tasks`

## Objective
Keep the v1.6 ONNX Runtime worker (DirectML/CPU) for AMD, Intel and CPU users, and add a faster path for NVIDIA CUDA users, with the installer/runtime selecting the backend automatically. Fix v1.6 decoder accuracy.

## Why
Benchmark 2026-11-07 (`odd/tasks/asr-benchmark-v15-v16.md`, ADR-018 untracked): v1.6 DirectML is 2.3-4.0x slower than v1.5.1 CTranslate2 CUDA, uses more RAM/VRAM, and dropped the final phrase of es_cortacreo (greedy + 1.2 repetition penalty, `beam_size` ignored).

## Success case (user, 2026-11-07)
Not one world or the other: NVIDIA/CUDA users get the fastest engine; AMD/Intel/CPU users keep DirectML/CPU; the installer manages the configuration.

## Constraints
- Subagents: sonnet (complex) / haiku (lightweight). No commits (approval required). TDD strict for product code (runner `cargo test -p liveaudio-asr-worker`).
- GPU measurements must be exclusive: acquire `<scratchpad>/bench/gpu.lock` (create-exclusive) before any GPU run, delete after; wait/retry if present.
- Bench harness and converted clips: `<scratchpad>/bench/` (scripts/drive_worker.mjs, audio/, results/). Clips are personal data: local only.
