## Outcome

Add optional local RNNoise suppression to the shared desktop/CLI audio pipeline and optional LiveAudio acoustic speech start/end metadata for downstream integrations. Existing transcription, subtitles, and OBS remain unchanged by default. These events do not implement conversation interruption or OpenCohost policy.

## Decisions and evidence

- The common CPAL path emits mono 16 kHz chunks of 512 samples (32 ms). Desktop and CLI use one DSP integration point; do not create separate denoising loops.
- Use `nnnoiseless` 0.5.2, a Rust port of RNNoise with a built-in model, rather than reimplementing DSP or shipping a native runtime. The exact API documents `DenoiseState::FRAME_SIZE` (480 samples), 48 kHz mono, `f32` values scaled like signed i16 PCM (`[-32768, 32767]`), stateful frames, and first-output fade-in artifacts. The published crate's `COPYING` is BSD-3-Clause. Bundle the crate/model in the ordinary desktop and CLI artifacts; neither first run nor runtime may download a model.
- Prefer applying DSP at 48 kHz before the existing final 16 kHz resample when the source path provides 48 kHz. Otherwise use bounded, stateful sample-rate adaptation. Convert normalized samples to/from i16 scale with finite/range checks. Preserve resampler and frame remainder across chunks: each 512-sample 16 kHz chunk expands to 1536 samples at 48 kHz, which is not divisible by 480; do not reset the frame adapter at chunk boundaries.
- Prime each new denoiser state with a synthetic 480-sample silence frame before user capture is considered active. The real algorithm's overlap-add returns the preceding 480-sample frame, so the adapter withholds each output until its corresponding input frame is due, discards only the priming silence output, and processes one synthetic silence drain frame at EOF to release the final valid tail. This adds the intrinsic 10 ms frame latency (160 samples at 16 kHz), within the approved ≤64 ms target; it avoids dropping or shifting speech without increasing the fixed-size buffer budget.
- Existing VAD transitions define acoustic event boundaries; denoised audio feeds the existing VAD/ASR path. Do not add a second detector.
- The app's Rust WebSocket binds to loopback, applies an Origin filter, sends `hello` with `proto: 1`, replays subtitle cues to late joiners, and ignores inbound messages. There is no per-client subscription handshake. Preserve the handshake, protocol version, and subtitle frames.
- In-repo OBS/browser source behavior is the only compatibility guarantee: it ignores unknown typed messages without subtitle text. Tolerance of arbitrary external text-only consumers is unverified. The explicit app-level event switch sends events to every connected client; per-client negotiation is out of scope. Never add events to subtitle replay or reconnect history.
- `AudioChunk.timestamp_ns` is wall-clock despite its monotonic comment. Event timing uses a separate attempt-scoped monotonic elapsed clock; broad timestamp cleanup is out of scope.

**Pinned dependency evidence:** [nnnoiseless 0.5.2 `DenoiseState` API](https://docs.rs/nnnoiseless/0.5.2/nnnoiseless/struct.DenoiseState.html) and the [0.5.2 crate `COPYING` file](https://docs.rs/crate/nnnoiseless/0.5.2/source/COPYING). The API page describes the bundled model and frame/scaling contract; the license file contains BSD-3-Clause terms. CPU suitability is a target to measure, not a claim already proven.

## Scope

### Included

- Persisted `rnnoise_enabled`, default `false`, exposed through canonical Rust config, desktop settings, and CLI-supported config. Legacy config omission defaults off. Persisted `acoustic_events_enabled`, default `false`, gates WebSocket event emission.
- Profile semantics for each flag: omission preserves the current value; explicit `true` or `false` applies that value. Reset/new-config defaults remain off.
- One shared RNNoise path with bounded streaming frame/rate adaptation before existing VAD/ASR, no capture-callback blocking, an implementation-plan-derived fixed buffering cap, and the bundled model in offline desktop/CLI artifacts.
- Acoustic event contract below, emitted only when its setting is enabled.
- Desktop bilingual setting/help copy that calls these **metadata-only acoustic start/end events** and explicitly says OpenCohost interruption/cancellation is not implemented.

### Excluded

AEC, playback-reference plumbing, duplex capture, OpenCohost consumption/interruption/ASR cancellation, per-client WebSocket subscriptions, new cloud services, runtime model downloads, persistent audio/event payload capture, broad timestamp refactors, and unrelated queues/performance refactors.

## Configuration and restart behavior

Both booleans are opt-in. When RNNoise is off, existing audio processing remains unchanged. When it is on, initialize DSP before reporting it active. If initialization or frame processing fails, do not silently claim successful bypass: use the existing actionable service-error path, keep the saved preference recoverable, and do not report the denoiser active.

For a running service, show the existing restart confirmation **before saving**. Cancel leaves saved config and active runtime config unchanged. After confirmation, persist the setting first; only after successful persistence may restart/apply mutate runtime state. A persistence failure must not restart or change active config. A restart failure leaves the persisted selection available for recovery and reports that runtime application failed.

No raw audio, denoised samples, transcript text, or event payload contents may be added to logs, diagnostics, session files, or other persistence.

## Acoustic event wire contract

Emit standalone JSON text frames over the current local WebSocket only when `acoustic_events_enabled` is true. Since the switch is app-wide rather than per-client, all connected clients receive them. Keep `hello` (`proto: 1`), Origin/bind security, subtitle payloads, and subtitle replay unchanged. Events are transient and never enter subtitle replay, the global WebSocket retry buffer, or history. New/reconnected clients see only future transitions; an event already in progress is not replayed or synthesized.

| Field | Contract |
|---|---|
| `type` | `speech_activity_start` or `speech_activity_end` |
| `event_version` | Integer `1` |
| `run_id` | Opaque unique identifier for one service run |
| `attempt_id` | Monotonically increasing integer for a capture/VAD attempt; changes only when capture/VAD actually restarts or resets |
| `utterance_id` | Opaque identifier allocated at start and repeated by its matching end |
| `seq` | Increasing event sequence within `run_id`; gaps are allowed and signal unobserved events |
| `monotonic_ms` | Attempt-relative elapsed monotonic milliseconds, never wall-clock time |
| `reason` | End only: `silence`, `duration_limit`, `service_stopped`, `capture_error`, or `attempt_reset` |

Example start: `{"type":"speech_activity_start","event_version":1,"run_id":"<opaque>","attempt_id":1,"utterance_id":"<opaque>","seq":7,"monotonic_ms":1250}`
Example end: `{"type":"speech_activity_end","event_version":1,"run_id":"<same>","attempt_id":1,"utterance_id":"<same>","seq":19,"monotonic_ms":3420,"reason":"silence"}`

Emit actual VAD transitions in order through each connected client's FIFO. Use a live-only send path that bypasses both subtitle replay and the shared retry buffer; if a connected client's queue is full, drop that frame for that client and record the existing bounded transport/drop diagnostic rather than deferring it to a future connection. Backpressure may create sequence gaps; unmatched ends are ignored, and clients expire unmatched starts or clear state on a new attempt. On a genuine capture/VAD stop, failure, or reset, emit exactly one matching end for an active utterance when delivery is possible, with the appropriate reason; then advance attempt identity. Late events from a prior attempt must not be mistaken for current state.

WebSocket disconnect/reconnect is transport-local: it MUST NOT stop/reset audio capture or VAD, close an utterance, or advance `attempt_id`. If a client disconnects after start, the reconnect receives no replay; a later end may be unmatched and must be ignored. Reconnection never generates a synthetic start/end or current-speech snapshot.

## Acceptance scenarios

1. **Default and compatibility:** Given new or legacy config, when desktop or CLI starts without enabling either option, then both flags are off, 16 kHz audio behavior and subtitle/hello frames are unchanged, and no acoustic frames are sent. Given the in-repo OBS/browser source receives a typed event without `text`, then it neither renders nor clears/corrupts subtitles. External consumers are explicitly not guaranteed compatible; with the setting enabled all connected clients receive events.
2. **RNNoise correctness and performance target:** Given synthetic generated (non-private) input and RNNoise enabled, then desktop and CLI use the shared processor; frame inputs are exactly 480 samples at 48 kHz in finite i16-scale `f32`, output is safely returned to normalized finite samples, state/remainder persists across 512-sample chunks, and the first user speech frame is not discarded. A deterministic 60-second synthetic pipeline test must show no unbounded backlog and no additional DSP drops relative to input. A release-build performance run on a recorded supported target CPU must achieve real-time factor `< 1` and proposed added DSP staging delay `<= 64 ms` excluding drivers and inference. These are targets pending measurement, not historical results. The implementation plan must derive and record the fixed buffer cap from frame/resampler state before any source write; on cap/overload, use bounded existing drop/error diagnostics rather than silently losing samples or adding a broad queue/refactor. Performance proof is manual and blocked if the supported target is unavailable; deterministic correctness tests remain separate.
3. **Offline package and failure:** Given release desktop and CLI artifacts are tested with network unavailable, then each includes the dependency and built-in model and runs without model downloads. Given DSP initialization/frame processing fails, then LiveAudio reports an actionable error and does not claim denoising is active or silently succeed with bypass audio.
4. **Persistence/profile UX:** Given either flag is changed while running, then restart confirmation occurs before save; cancel changes neither saved nor active config. After confirmation, successful persistence precedes restart/apply; persistence failure does not mutate active state. For each profile and each flag, omission preserves the current value while explicit `true`/`false` applies. Both flags round-trip save/reload; reset/new configs default off.
5. **Acoustic transitions:** Given events are enabled and VAD transitions idle → speech → idle, then exactly one ordered start/end pair shares `run_id`, `attempt_id`, `utterance_id`; `seq` and monotonic time increase and end has a valid reason. Given actual capture/VAD reset or stop during speech, then a matching end is attempted and the next attempt has a new ID. Given only WebSocket disconnect/reconnect during speech, then capture/VAD and attempt continue unchanged, no event is replayed, and any later unmatched end is ignored.
6. **Metadata-only/privacy:** Given either option is used, UI/help calls event output metadata-only and OpenCohost cancellation pending/out of scope; diagnostics/session output contains no new raw audio, denoised samples, transcript/event payload contents, or event history.

**Buffering and latency decision (fixed before source writes):** Keep the processor synchronous on the existing non-capture worker path; do not add a queue. Persistent staging is capped at one incomplete RNNoise input frame (at most 479 of 480 samples at 48 kHz, 9.98 ms) plus one incomplete 16 kHz VAD output chunk (at most 511 samples, 31.94 ms), plus fixed-size metadata: one source timestamp, one output sequence, and frame/phase counters. The processor consumes one 512-sample 16 kHz input chunk at a time, feeds the 48 kHz frame adapter incrementally (never appending an entire converted chunk to the retained frame remainder), and returns at most two complete 512-sample `AudioChunk`s per call; its returned batch has capacity two. The one 480-sample DSP scratch frame is reused in place. Thus internal persistent sample staging is fixed at 990 samples, while per-call input, frame scratch, and output are also bounded (at most 512 + 480 + 1,024 additional samples); no per-sample metadata queue is allowed. The processor returns an error through the existing actionable service-error path if a bound would be exceeded; no silent trim/drop or bypass. On clean stop, zero-pad only the final incomplete RNNoise frame, retain only output corresponding to real input samples, then use the existing final-resampler flush contract to zero-pad a final partial VAD chunk to 512; this preserves its real sample prefix and never treats the pad as captured speech. Capture failure attempts that same flush only while the processor remains usable, then closes active event state with `capture_error`.

**Added DSP staging latency** is the maximum observed incremental delay for a logical sample to reach the 16 kHz/512-sample VAD boundary in the enabled path minus the corresponding boundary delay for the same timestamped synthetic input in the bypass path. It includes added frame-alignment wait, DSP service time, conversion state, and complete-output-chunk assembly; it excludes the common capture/driver schedule, existing bypass-path chunk collection, and VAD/ASR inference. Measure it in a paced 60-second run with per-sample source-index/timestamp alignment, not in an unpaced unit test and not by checking only that a buffer is non-empty. The target remains ≤64 ms. RED tests must prove five 512-sample inputs (2,560 samples) map to sixteen 160-sample 16 kHz frame periods, the first user speech sample remains aligned after silence prewarm, persistent caps hold after every call, each call returns 0–2 complete chunks, and clean flush preserves the valid tail. If any premise fails, stop for plan/spec review rather than changing a bound implicitly.

**Sample-rate placement trade-off (approved):** The processor inserts at the shared 16 kHz `AudioChunk` seam (after CPAL's existing hardware→16 kHz `AudioResampler`), then statefully adapts 16→48 kHz for RNNoise and 48→16 kHz for its output. This deliberately chooses a narrow shared desktop/CLI integration and avoids restructuring the capture/resampler pipeline, but it does **not** implement the spec's preferred 48 kHz-before-final-16 kHz placement when the device already supplies 48 kHz. This explicit fidelity/CPU/latency trade-off was accepted by the Product Owner. The RNNoise frame API and full-frame correctness tests remain 48 kHz.

**Public lifecycle API:** `AcousticEventLifecycle::new() -> Self` creates one fresh run and attempt; `observe_vad_transition(&mut self, transition: VadTransition, at: Instant) -> Option<AcousticSpeechEvent>` maps only `SpeechStart` and `SpeechEnd` (silence→`Silence`, max duration→`DurationLimit`); `close_attempt(&mut self, reason: AcousticSpeechEndReason, at: Instant) -> Option<AcousticSpeechEvent>` emits at most one matching end and clears active state; `start_attempt(&mut self, at: Instant) -> u64` advances attempt identity and resets only the attempt clock. A private monotonic-per-process nonce plus process/time entropy creates opaque run/utterance IDs; `seq` increases across attempts in the run. Call `start_attempt` only after capture/VAD actually starts or resets, never on WebSocket reconnect.
**Network API:** Add the inherent `WsServer::broadcast_acoustic_event(&self, event: &AcousticSpeechEvent) -> Result<(), NetworkError>` in `crates/liveaudio-network/src/server.rs`; export only any required public event types through `crates/liveaudio-network/src/lib.rs`. The existing `NetworkServer` trait currently exposes only `broadcast_cue(&self, cue: &TranscriptionCue) -> Result<(), NetworkError>`; keep acoustic delivery an inherent `WsServer` method because desktop and CLI already own concrete `WsServer`s and this is not subtitle-sink behavior. Serialize one standalone JSON text frame, hold `clients.read()` while taking the connected-client membership snapshot and calling each sender's nonblocking `try_send`, and never call `broadcast_raw`, subtitle/replay insertion, or retry-buffer logic. Connection registration requires the corresponding clients write lock, so this read-locked publish is the atomic membership boundary: clients registered after it cannot receive that past event. Queue-full frames are dropped for that client, increment the existing bounded backpressure metric/diagnostic, and are not retained.
**Consumers:** In both `desktop/src-tauri/src/commands.rs` and `crates/liveaudio-cli/src/main.rs`, use the shared `AcousticEventLifecycle` at the existing `VadTransition` handling point and publish only when `config.acoustic_events_enabled`. On genuine service stop, capture failure, or VAD reset, call `close_attempt` with its reason; advance the attempt only after a real capture/VAD restart. All connected clients receive events when the app-level flag is true; no per-client subscription is introduced.
